# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repository is

Danny's personal NixOS + desktop configuration. There is **no application code, no build
system, no test suite** — everything here is declarative configuration (Nix), window-manager
/ bar / launcher config files, and reference docs.

It covers two machines:

| Host | Flake dir | Role |
|---|---|---|
| `nixos` | repo root | Intel laptop desktop — GNOME + Hyprland, home-manager, rclone backups |
| `asus-worker` | `asus-worker/` | Headless homelab node — k3s **agent** joining `192.168.0.10` |

The repo is checked out over the user's home directory (`~`), which is why `.zshrc` and
`.config/` are tracked at the top level. The Nix files also live at `/etc/nixos/` on the
real machine — `CHEATSHEET.md` and `CONFIG-VS-HOME.md` refer to that path, and it is the
path the rebuild commands are run from.

## Layout

```
flake.nix / flake.lock          # host "nixos" — desktop flake (ACTIVE)
configuration.nix               # system-level config for "nixos"
hardware-configuration.nix      # generated by nixos-generate-config; do not hand-edit
home.nix                        # home-manager config for user "danny"
packages/snd-hda-cs8409.nix     # out-of-tree kernel module derivation (currently UNREFERENCED)

dotfiles/                       # SOURCE of truth for HM-managed configs (hypr, waybar, rofi, wofi, wlogout)
.config/                        # copies of the above + configs NOT managed by home-manager
.zshrc                          # standalone; not generated by home-manager

asus-worker/                    # host "asus-worker" — separate, self-contained flake (ACTIVE)
nixos/                          # STALE earlier snapshot of the root config — see below
CHEATSHEET.md                   # day-to-day command reference
CONFIG-VS-HOME.md               # decision guide: configuration.nix vs home.nix
```

## Applying changes

There is nothing to compile or test locally. The only "build" is a NixOS rebuild, and it
must be run on the target machine (it needs root and the real hardware config).

```bash
# desktop host, from /etc/nixos — applies configuration.nix AND home.nix together
sudo nixos-rebuild switch --flake .#nixos

# homelab node, from the asus-worker checkout on that machine
sudo nixos-rebuild switch --flake .#asus-worker

# safer dry runs
sudo nixos-rebuild build --flake .#nixos    # build only, don't activate
sudo nixos-rebuild test  --flake .#nixos    # activate, but don't add a boot entry

# syntax/eval check without switching
nix flake check
```

Updating inputs:

```bash
sudo nix flake update                       # all inputs
sudo nix flake lock --update-input <name>   # just one, e.g. zen-browser
```

In this sandbox/CI-style environment a rebuild is not possible — validate edits by reading
and, at most, `nix flake check` / `nix eval`. Never claim a config change was verified on
hardware.

## Editing conventions

**Golden rule: never edit `~/.config/<app>` for anything home-manager owns.** Those paths
are symlinks into the read-only Nix store. Edit the source under `dotfiles/` (or the
relevant `.nix` file) and rebuild.

Which file to touch:

| Change | File |
|---|---|
| System packages, users, boot, networking, services | `configuration.nix` |
| Flake inputs | `flake.nix` |
| git identity, zsh, starship, ghostty, neovim | `home.nix` |
| Hyprland / Waybar / rofi / wofi / wlogout | `dotfiles/<app>/…` (wired up in `home.nix`) |
| Anything homelab/k3s | `asus-worker/configuration.nix` |

`home.nix` passes whole directories through with `home.file.".config/<app>" = { source =
./dotfiles/<app>; recursive = true; }` — so a new file dropped into `dotfiles/waybar/`
is picked up automatically, no `home.nix` edit needed. Adding a *new* app directory does
require a new `home.file` block.

## Repository quirks — read before editing

These are real, currently-true inconsistencies. Don't "fix" them silently; they change
behaviour on a live machine.

- **`dotfiles/` and `.config/` are byte-for-byte duplicates** for `hypr`, `waybar`,
  `rofi`, `wofi`, and `wlogout`. `dotfiles/` is the live source (home-manager reads it);
  the `.config/` copies are committed snapshots that home-manager will overwrite/symlink
  over. **When changing one of those apps, update `dotfiles/` — and update the `.config/`
  copy too, or the two drift.** `.config/` also holds configs home-manager does *not*
  manage (`btop`, `htop`, `kitty`, `gtk-*`, `quickshell`, `starship.toml`) — those are
  edited in place.
- **`nixos/` is a stale snapshot** of an older root config (pre-home-manager: no
  `home.nix`, still has the removed `networking.wg-quick.interfaces.wg0` block that
  conflicted with NetworkManager, no `brave`, old `enableAutosuggestions` option name).
  Its `hardware-configuration.nix` and `packages/` are identical to the root copies.
  Nothing imports it. Treat the **repo root** as the desktop config; only touch `nixos/`
  if explicitly asked.
- **`flake.lock` is stale on purpose after the home-manager fix.** `home-manager` is now a
  declared input (`release-26.05`, with `inputs.nixpkgs.follows = "nixpkgs"`), but the
  committed lock still carries the old *indirect* registry node that pulled its own
  `nixpkgs-unstable`. Nix rewrites the lock automatically on the next rebuild because the
  input declaration changed — **the first rebuild after this change will produce a
  `flake.lock` diff, and that is expected**. Commit the regenerated lock.
- **`networking.wireless.enable` and `networking.networkmanager.enable` are both `true`**
  in `configuration.nix` (lines 26–27). That runs standalone `wpa_supplicant` alongside
  NetworkManager, which also uses wpa_supplicant as its own backend — the two can fight
  over the wireless interface. NetworkManager is the one actually in charge here (GNOME's
  WiFi panel and `wg0` both depend on it), so `networking.wireless.enable` is very likely
  the line to drop. **Left as-is deliberately**: it can't be validated without the real
  radio, and getting it wrong means no WiFi on a laptop. Confirm with the user before
  changing it.
- **`packages/snd-hda-cs8409.nix` is dead config.** It builds the Cirrus CS8409 codec
  driver (2016/2017 MacBook Pro speakers) from `davidjo/snd_hda_macbookpro` at a pinned
  rev, but no `boot.extraModulePackages` anywhere references it. The upstream driver
  source is **not** vendored in this repo — only the derivation. Wiring it in requires
  `boot.extraModulePackages = [ (config.boot.kernelPackages.callPackage ./packages/snd-hda-cs8409.nix {}) ]`
  plus a `sha256` refresh if the pinned rev moves.
- **Both GNOME and Hyprland are enabled** in `configuration.nix`. GNOME is the day-to-day
  session; the Hyprland/Waybar configs exist and are deployed but aren't the primary
  desktop. NetworkManager cannot be removed — GNOME's WiFi panel depends on it.
- **One rclone backup unit**, `rclone-sync`, firing every 5 minutes via
  `OnCalendar = "*:0/5"`. An hourly `gdrive-personal-sync` pair running the byte-identical
  `rclone copy` was removed; a comment marks where it was. The remote (`NixosBackup:`) is
  configured in `~/.config/rclone/`, which is gitignored.
- **git identity differs by source**: `home.nix` sets `danny.rudd@icloud.com`; commits in
  this repo may use a different address. Match whatever the repo's recent history uses.
- **Formatting in the `.nix` files is inconsistent** (mixed tabs and spaces, irregular
  indentation, commented-out blocks kept as history). Match the surrounding style of the
  block you edit rather than reformatting the file — a whole-file reformat buries the
  actual change in diff noise.
- **Stale editor/backup files are tracked**: `kitty.conf.bak`, `kitty.conf.save`,
  `waybar/style.css.save`, `*.backup`, `waybar/config.js` (an unused alternate layout).
  `*.backup` is gitignored going forward; the already-committed ones are not.

## Secrets

`.gitignore` excludes `.ssh/`, `.gnupg/`, `.config/rclone/`, `.claude/`, `.claude.json`,
shell histories, and `*.backup`. Secrets are referenced by path, never inlined:

- `asus-worker/configuration.nix` reads the k3s join token from `/etc/k3s-token` (on-disk,
  out of git).
- `asus-worker` sets `initialPassword = "changeme"` — a bootstrap value, not a real secret.
- WireGuard config lives at `/etc/wireguard/wg0.conf`, managed by NetworkManager on the
  desktop, not by Nix.

Never commit a token, key, or `wg0.conf` into this repo, and don't add secret values to
`.nix` files — everything in the Nix store is world-readable.

## Host details worth knowing

**`nixos` (desktop)** — `system.stateVersion = "26.05"`, `nixpkgs` pinned to `nixos-26.05`,
timezone `Australia/Sydney`, locale `en_AU.UTF-8`, keymap `au`. Pipewire (PulseAudio off),
systemd-boot + EFI, Tailscale, OpenSSH, unfree packages allowed, weekly `nix.gc` with
`--delete-older-than 7d`, and `nix.settings.auto-optimise-store`. UDP 51820 (WireGuard) is
open. `home-manager.backupFileExtension = "backup"` is set in `flake.nix` — after large
`home.nix` changes, check for new `.backup` files that may need merging back in.

**`asus-worker`** — static IP `192.168.0.11/24`, gateway `192.168.0.1`, DNS
`192.168.0.10` then `1.1.1.1`. Firewall opens TCP 22 + 10250 (kubelet) and UDP 8472
(flannel VXLAN). k3s agent pointed at `https://192.168.0.10:6443`. Flakes are opted in via
`nix.settings.experimental-features`. It has **no home-manager and no flake inputs beyond
nixpkgs** — keep it minimal and self-contained; don't import root-level files into it.
